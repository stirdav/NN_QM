# Conditionally-squeezed states

Reproduces Fig. 1 and Fig. 4 of Hope, Lidal & Massel, "Preparation of
conditionally-squeezed states in qubit-oscillator systems",
[arXiv:2504.01664](https://arxiv.org/abs/2504.01664), Phys. Rev. Research
(2026), using the `QuantumDynamics` framework rather than raw
`QuantumOptics.jl`.

- `system.jl` — shared `CompositeSystem` (`build_system`, taking `ωm` as a
  keyword so it isn't pinned to Fig. 4's device parameters), the paper's
  `Hcs`/`H1` Hamiltonians (Eq. 4 / Eq. S4), and the conditional-measurement
  helper used by all three figures.
- `fig1_squeezed_superpositions.jl` — closed-system protocol: evolve under
  `Hcs`, projectively measure the qubit in the σx basis, plot the Wigner
  functions of the resulting symmetric/antisymmetric squeezed-state
  superpositions → `fig1.png`.
- `fig2_sensitivity_sweep.jl` — closed-system sensitivity sweep: fidelity
  between the symmetric superposition generated by `Hcs` and the same
  state generated by `H1` (an exact rewrite of the full lab-frame
  Hamiltonian, Eq. 1, with no RWA applied — unlike `Hcs`), as either the
  drive amplitude Ā=2A/ωd (panel a) or the relative coupling strength g/ωm
  (panel b) is displaced from its ideal value → `fig2.png`. Cross-validated
  against the paper's own reference implementation and saved simulation
  output (github.com/mariuskh/arXiv-2504.01664) to 5 significant figures.
- `fig4_open_system_fidelity.jl` — open-system evolution under `H1` with
  qubit decay/dephasing and a thermal oscillator bath; plots fidelity of the
  conditioned oscillator state against the noiseless reference trajectory,
  for four `(γ1/g, γφ/g)` combinations → `fig4.png`.
- `lab_frame_benchmark.jl` — not a paper figure: a single closed-system run
  at Fig. 2's own best operating point (Ā=2.405, g/ωm=0.001), comparing
  `evolve`'s wall-clock cost between `H1` (interaction frame, ωq rotated
  away) and a new `Hlab` (Eq. 1 + Eq. 2, lab frame, ωq resolved explicitly)
  — the point being that `H1` is an *exact* rotating-frame rewrite of
  `Hlab` (no approximation, unlike `Hcs`), so both should reproduce the
  same physics at very different cost. Sanity-checked by transforming the
  `Hlab` trajectory into the interaction frame via the same unitary `H1` is
  derived from (Eq. S3) and confirming it matches `H1`'s own trajectory to
  solver tolerance, rather than trusting cost alone. Prints timings and the
  transform-fidelity range to stdout; produces no plot.
- `lab_frame_benchmark_open_system.jl` — open-system analogue of
  `lab_frame_benchmark.jl`: the same `H1`-vs-`Hlab` cost/sanity comparison,
  now with dissipation, at Fig. 4's best (lowest-decoherence) rate
  combination `γ1/g, γφ/g = 0.1, 0.1` rather than a sweep over all four.
  Uses the same `J` (built from `Decay`/`Dephasing`/`thermal_bath`, as in
  `fig4_open_system_fidelity.jl`) unchanged in both frames — `V1`'s adjoint
  action is a pure phase on each jump operator here, and a Lindblad
  dissipator is invariant under a phase on its operator, so the sanity
  check is the density-matrix analogue of the closed-system script's:
  `ρ_int(t) = V1(t) ρ_lab(t) V1(t)'`. Runs at Fig. 2's `ωm/g=1000` rather
  than Fig. 4's own `ωm/g=1e4` — resolving the lab frame's fast `ωq`
  oscillation is far more expensive for the master equation (density
  matrix) than for the closed-system Schrödinger equation (state vector);
  at Fig. 4's real `ωm` combined with the paper's `ωq/ωm=20` device ratio,
  the default explicit ODE solver becomes numerically unstable before
  reaching `gt=1.2` at all. `ωm/g=1000` keeps `ωq/ωm=20` intact while
  staying in a regime `fig2_sensitivity_sweep.jl` already validates as an
  excellent RWA approximation.
- `lab_frame_conditional_squeezing_check.jl` — visual sanity check: runs
  the same open-system lab-frame trajectory as
  `lab_frame_benchmark_open_system.jl`, then projects the qubit to recover
  Fig. 1's conditionally-squeezed oscillator states, checking that `Hlab`
  reproduces the paper's actual state-preparation protocol end-to-end, not
  just the state-fidelity numbers the benchmark scripts report. Plots two
  versions side by side: conditioning after first rotating the final state
  into the interaction frame via `V1(t_final)` (the physically correct
  measurement — `fig1`/`fig4`'s fixed `|±⟩=(|e⟩±|g⟩)/√2` projector is only
  stationary in that frame), and conditioning the raw lab-frame state on
  the same fixed `|±⟩` with no correction, to make the frame mismatch
  visible rather than just asserted → `lab_frame_conditional_squeezing_check.png`
  (top row: recognizable Fig. 1 bowtie pattern, axis-aligned, softened by
  dissipation; bottom row: same kind of squeezed state but rotated ~45°
  off-axis — a real answer, just not the one the protocol is meant to
  prepare, from measuring the qubit in an uncontrolled, still-precessing
  basis).

Fig. 3 (a purely analytic Fock-basis calculation, no time evolution) is
intentionally out of scope.

## Running

```sh
julia --project=. fig1_squeezed_superpositions.jl
julia --project=. fig2_sensitivity_sweep.jl
julia --project=. fig4_open_system_fidelity.jl
julia --project=. lab_frame_benchmark.jl
julia --project=. lab_frame_benchmark_open_system.jl
julia --project=. lab_frame_conditional_squeezing_check.jl
```

`Project.toml` points `QuantumDynamics` at the package root via Julia's
`[sources]` table, so no separate install/dev step is needed.

## A note on `nmax`

`fig2_sensitivity_sweep.jl`'s fidelity comparisons are sensitive to the
oscillator's Fock-space cutoff `nmax`: an undersized cutoff undershoots the
converged fidelity (e.g. `nmax=25` vs. `nmax=50` differed by ~0.004 at one
of Fig. 2's data points) without erroring, so on its own it fails silently
rather than loudly. `fig2_sensitivity_sweep.jl` now guards against this with
`check_fock_cutoff` (`src/measurement.jl`), which throws if population near
the truncation boundary exceeds a tolerance instead of letting an
under-converged result through quietly — but that only catches truncation
*this* severe or worse; it's not a substitute for checking that the
fidelities themselves are converged to the precision you actually need
(e.g. by rerunning with a larger `nmax` and confirming the values don't move
at that precision) rather than assuming a value that "looks converged" from
a plot actually is.
